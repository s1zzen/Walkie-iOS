# Walkie Field Lab

Отдельное SwiftUI-приложение для полевых экспериментов Сергея: план прогулки, запись Core Location/Core Motion, два онлайн-детектора схода и ручные отметки. iPhone с iOS 17+, без сторонних библиотек, API-ключей, AR и Яндекс Карт.

Это инструмент сбора данных, не готовый навигатор. Он не устанавливает факт глушения или подмены спутникового сигнала и не гарантирует исправление координат.

## Установка на iPhone

1. Открыть `WalkieFieldLab.xcodeproj` в Xcode. Нужен Xcode 16 или новее; проект проверяется с Xcode 26.4.1.
2. Target **WalkieFieldLab → Signing & Capabilities → Team**: выбрать свой Apple Development Team. Automatic signing уже включён. Если идентификатор занят, заменить `dev.walkie.FieldLab` на свой уникальный.
3. Подключить iPhone, подтвердить доверие компьютеру и при необходимости включить Developer Mode в настройках телефона. Выбрать iPhone в качестве устройства запуска и выполнить Run.
4. В приложении открыть «Тест» → «Разрешить геолокацию и движение». Для опыта нужна точная геопозиция и доступ к Motion & Fitness. Если разрешение отклонено, изменить его в настройках iOS.
5. После установки запускать приложение обычным нажатием на иконку. Полевой тест лучше проводить без подключённого отладчика: он может менять поведение приложения в фоне.

Пароли и токены в проект не нужны. Подпись для физического телефона выполняется твоей учётной записью в Xcode; неподписанная проверочная сборка сама по себе на iPhone не устанавливается.

## Как задать маршрут

### На карте

Переместить карту так, чтобы крестик оказался в нужной точке, и нажать «Точка». Повторить для следующих точек.

- **Пеший путь:** 2–8 точек; Apple MapKit запрашивает пешие участки между ними. Нужен интернет и покрытие сервиса. В некоторых местах построение недоступно — приложение покажет ошибку, не подменяя маршрут прямой линией.
- **Ручная линия:** 2–100 точек соединяются напрямую. Нужно поставить точки на каждом повороте, вдоль реально проходимого пути. Это не поиск дорог и не проверка безопасности прохода.
- Имя и полученная геометрия сохраняются в `Documents/Routes`. Маршрут можно снова выбрать через меню папки вверху.

Начальная карта показывает центр Москвы. Начальная геопозиция не используется как истинная точка старта: при плохом сигнале план задаётся независимо от неё. Синяя линия — план, оранжевый маркер — последнее системное измерение, не эталон.

### GPX

Меню папки → «Импорт GPX» → выбрать файл в «Файлах».

Поддерживаются `trk/trkseg/trkpt` и `rte/rtept`. Отдельные сегменты остаются раздельными: разрыв не превращается в выдуманный прямой переход. Лимиты: 5 МБ и 10 000 точек; пустые, одноточечные и повреждённые сегменты отклоняются. GPX с DTD/XML-сущностями запрещён. Только список waypoints (`wpt`) не считается маршрутом.

Геометрия фиксируется на время записи. Перестроение и смена плана во время теста запрещены.

## Первая прогулка

1. Задать знакомый безопасный маршрут и открыть вкладку «Тест».
2. Внести условия: район, телефон в руке/кармане, особенности погоды/окружения. Нажать «Начать запись» в открытом приложении.
3. В начале нажать «Я на маршруте» и отметить положение телефона. Обычные остановки и повороты тоже полезны для опыта.
4. При осознанном безопасном отклонении нажать «Я сошёл с маршрута», при возвращении — «Я на маршруте». Не ориентироваться на решения алгоритмов при разметке. Точность времени нажатия ограничена реакцией человека.
5. Если координаты явно не соответствуют месту, нажать «Координаты явно неверные». У узнаваемого места можно добавить «Ориентир» с названием. Это текстовая отметка, не геодезическая координата.
6. Отдельно проверить несколько минут с заблокированным экраном. Принудительно не закрывать приложение; это остановит наблюдения. После возвращения обратить внимание на предупреждения о паузах.
7. Нажать «Завершить и сохранить». Открыть «Логи» либо «Файлы» и передать папку прогулки целиком.

Безопасность важнее отметки: не пользоваться экраном при переходе дороги. Для более точной независимой разметки нужен наблюдатель или иной протокол. Не надо специально создавать радиопомехи — фиксируем встречающиеся условия.

## Где лежат данные

**Файлы → Обзор → На моём iPhone → Walkie Field Lab → Sessions → папка с датой и идентификатором.**

Папка создаётся в момент старта. Логи дописываются во время теста, а не держатся только в памяти до завершения. Во вкладке «Логи» есть сводка и системное меню передачи отдельных/всех файлов. Для одного переносимого архива можно сжать завершённую папку средствами «Файлов».

| Файл | Содержимое |
| --- | --- |
| `meta.json` | Версия схемы/приложения, даты, устройство/ОС, заметки, конфигурация, маршрут, флаг незавершённой записи |
| `route.json` | Зафиксированный план с отдельными сегментами и источником |
| `locations.jsonl` | Все полученные измерения Core Location, точность, скорость/course, времена измерения и доставки, флаги sourceInformation |
| `motion.jsonl` | Device Motion и шагомер; различаются полем `kind` |
| `events.jsonl` | Heartbeat, разрешения, lifecycle, ошибки, паузы и ручные отметки |
| `predictions.jsonl` | Ответы обоих алгоритмов, объяснения, расстояние до плана и однократные события предупреждения |
| `observed.gpx` | Наблюдаемый трек из допустимых по формату фиксаций — НЕ истинный и НЕ исправленный путь |
| `summary.json` | Итог при штатном завершении: длительность, количество измерений/отметок/предупреждений, время состояний |

JSONL — один JSON-объект на строку. Время календаря — UTC ISO8601 с долями секунды; `elapsed` — секунды с начала сессии по непрерывным монотонным часам, включая сон системы. Исходные timestamps датчиков сохранены отдельно. Не смешивать uptime-время Core Motion с `elapsed` без преобразования.

Для device motion записываются ускорение без гравитации и гравитация в **g**, угловая скорость в **рад/с**, углы ориентации в **радианах**, кватернион и название системы отсчёта. Запрашивается 20 Гц, фактическая доставка зависит от iOS. Направление телефона не называется направлением движения человека. Шаги/дистанция — накопительные показания с начала сессии; отсутствие данных не заменяется нулём.

GPX сохраняет в том числе подозрительные, но допустимые по формату координаты: это важно для исследования ошибок. Разрывы времени более 10 секунд, невалидные фиксы и нарушение порядка времён разделяют сегменты. При аварийном завершении последняя дописываемая часть GPX/JSONL может быть неполной; первичны сырые JSONL.

Ручные отметки лежат только в `events.jsonl` с `kind=manual_marker` и `details.kind` из `actual_on_route`, `actual_off_route`, `gps_wrong`, `phone_hand`, `phone_pocket`, `landmark`, `note`. Они **никогда не поступают в алгоритм**. Оценивать ложные тревоги автоматически по тем же GPS-координатам нельзя: поэтому итог не содержит выдуманных precision/recall.

## Какие алгоритмы действительно работают

### `geometric_v1`

Расстояние до всего зафиксированного плана, гистерезис: сход при расстоянии больше 25 м, возврат при расстоянии меньше 15 м. Изменение подтверждается последовательностью новых измерений на интервале не менее 4 секунд. Один старый фикс и heartbeat не подтверждают новое событие. Круговые/повторные участки плана не учитывают порядок прохождения.

### `guarded_v1`

Тот же геометрический детектор, но с предварительными проверками:

- заявленная горизонтальная погрешность не больше 35 м;
- допустимые и достаточно свежие timestamps;
- перемещение между фиксациями согласуется с мягким пешеходным пределом 4 м/с, запасом 20 м и заявленной точностью;
- при наличии последовательных свежих показаний шагомера проверяется грубая согласованность перемещения с количеством шагов;
- после подозрительного скачка — `uncertain` и карантин; возвращение в старую область либо минимум три согласованных фикса нового кластера за 20 секунд позволяют продолжить. Для нового кластера требуется новое временное подтверждение.

Без свежей геолокации более 10 секунд отображается неопределённость; длительный перерыв сбрасывает состояние. Задержанные фиксы сохраняются в сыром журнале, но не считаются актуальной позицией. Неопределённость — осознанный отказ от вывода, а не исправление координат. Шаговая проверка эвристическая, может ошибаться и не рассчитана на транспорт.

**Это не перенос прежнего HMM один в один и не PDR.** Для честного HMM нужны альтернативные дорожки пешеходной сети, а GPX/MapKit здесь дают только план. Для устойчивой PDR нужна отдельная оценка движения/ориентации. Данные уже записываются для следующих итераций и воспроизведения опытов.

Плавное систематическое смещение или устойчивый неправильный старт могут обмануть оба метода. Принятие нового кластера после карантина не доказывает правильность места. Пороги демонстрационные, не настроены на реальные московские данные. Уменьшение количества предупреждений само по себе не подтверждает исследовательскую гипотезу.

## Фон, сохранность и приватность

- Включён background mode `location`, запись запускается на переднем плане с разрешением When In Use. Это не гарантия непрерывной работы при любых условиях. Motion, шагомер и таймер могут доставляться с паузами.
- Heartbeat раз в секунду фиксирует выполнение процесса. Разрыв callbacks более 3 секунд отмечается явно; точную причину — sleep, suspension или задержку планировщика — приложение не утверждает. Такие промежутки в сводке консервативно относятся к неопределённости.
- Сохранение последовательное, синхронизация файлов примерно раз в 3 секунды и при завершении. Ошибка диска останавливает опыт с сообщением, а не маскируется как успешная запись.
- `interrupted=true` сохраняется с самого старта, а `false` — последним после штатного завершения. После аварии остаются частичные данные; восстановление сессии автоматически не продолжается. Последние несинхронизированные записи могут потеряться.
- Файлы доступны после первого разблокирования устройства, в том числе при последующей блокировке экрана. Это компромисс для фонового регистратора, не шифрование отдельным паролем.
- Собственного сервера/аналитики/отправки логов нет. Карта и построение маршрута используют сервисы Apple; запросы маршрутизации передают им выбранные точки. Системные резервные копии и ручной экспорт могут переносить файлы за пределы телефона. В папке — чувствительная история местоположений.
- Удаление приложения может удалить его локальные записи: сначала выгрузить нужные папки.

## Структура и проверки

`Sources/Core` — Foundation-модели, геометрия, алгоритмы, GPX/JSON. `Sources/App` — SwiftUI, MapKit, датчики и файловая запись. SwiftPM служит для независимых тестов ядра, а приложение собирается через Xcode-проект.

```sh
swift test
xcodebuild -project WalkieFieldLab.xcodeproj -scheme WalkieFieldLab \
  -configuration Debug -sdk iphoneos -destination 'generic/platform=iOS' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

При ограничениях окружения на общий module cache:

```sh
CLANG_MODULE_CACHE_PATH=/private/tmp/walkie-field-lab-module-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/private/tmp/walkie-field-lab-module-cache \
swift test --disable-sandbox --cache-path .build/cache
```

Тесты проверяют причинность, скачки/карантин/восстановление, пропуски, отсутствие повторного подтверждения одним фиксом, свежесть шагов, сферическую геометрию, GPX/XML и даты логов. Полевое качество алгоритмов, фон на реальном iPhone, расход батареи и доступность маршрутизации в конкретном районе проверяются отдельно.
